# 豆包漫剧自动生成

把小说章节或故事描述，转成豆包可批量生成的漫剧分镜视频。

## 平台硬约束（决定一切设计）

**豆包免费版单次生成最长 15 秒。** 这条约束贯穿整个技能：

- 每个镜头的时长必须 ≤ 15 秒，由拆解算法强制保证（15s 是**上限**，不是每镜固定值）
- 一章必然拆成多个镜头，**必须分多次单独生成**，不能指望一次出完整章
- 每镜单独消耗额度：**按生成次数计费，与视频时长无关**，每生成 1 个镜头计 1 次
- 提示词里必须显式写"时长N秒"，否则模型可能自行决定长度
- **分集规则**：默认每 5 个镜头为一集（≈60 秒，对齐主流微短剧单集 1–2 分钟）；连载章节的每集结尾必须停在高潮未解决处留悬念

## 执行流程

### 阶段 0：浏览器就绪（脚本自动完成）

生成脚本**零依赖、自包含**：直连 CDP（内置 WebSocket 客户端），自动拉起带调试端口的专用配置浏览器，无需任何 proxy 或外部 skill。CDP 客户端、浏览器管理、页面操作原语提取到项目根的 `shared/` 共享内核，所有 skill 脚本共用。

**必须先向用户展示此提示，再启动浏览器操作：**

```
温馨提示：部分站点对浏览器自动化操作检测严格，存在账号封禁风险。已内置防护措施但无法完全避免，Agent 继续操作即视为接受。
```

建议先跑一次连通性体检（不消耗生成额度）：

```bash
python skills/doubao-manju-video/scripts/doubao_gen.py --probe -o ./out
```

脚本行为：
- 检测 `--port`（默认 9222）是否已有可调试浏览器，有则直接复用
- 没有则自动拉起 **专用配置** 的 Edge（`%LOCALAPPDATA%\doubao-manju\edge-profile`），与用户日常浏览器并存互不干扰
- 打开豆包并报告：页面就绪 / 输入框 / 登录状态

**首次运行必须登录一次**：专用配置是独立登录态（与用户日常浏览器不共享）。未登录时脚本会提示用户在弹出的窗口扫码/手机号登录，并轮询等待（默认 600s），登录态持久保存，之后无需再登。**不要在专用窗口出现前就让用户去点日常浏览器的豆包**——登录必须发生在专用配置的窗口里。

三个常见坑（详见 `references/doubao-selector-guide.md`）：

| 现象 | 根因 | 解法 |
|------|------|------|
| 默认配置的 Edge 无法开调试端口 | Chromium 136+ 禁止在默认用户目录开远程调试（安全策略） | 这就是必须用专用 `--user-data-dir` 的原因，脚本已内置 |
| 调试端口起不来 | 9222 被占用，或已有同配置目录的窗口开着 | `--port 9223` 换端口；关掉旧的同配置窗口 |
| 用户日常 Edge 已登录豆包但不能复用 | 默认配置目录禁止调试端口，登录态也无法跨配置共享 | 让用户在专用窗口登录一次（持久有效） |

### 阶段 1：判断输入类型

| 输入形态 | 判断依据 | 走哪条路 |
|---------|---------|---------|
| 小说章节 | txt/md/epub 正文，含"第N章"、大段叙事白描 | 小说拆解模式 |
| 故事描述 | 用户口述设定、创意梗概、人物小传 | 概念拆解模式 |

**两者的区别在于谁来提供"情节"**：小说模式从正文提取情节；概念模式下情节尚未存在，需先由 WorkBuddy 生成故事方案。

### 阶段 2A：小说章节拆解

```bash
python skills/doubao-manju-video/scripts/split_novel.py <章节文件> -o ./out --style 3d-realistic --ratio 16:9
```

**拆解是双因子驱动的**（不是单纯按字数平均切）：

1. **字数密度** — 按中文叙述语速约 4.6 字/秒估算镜头容量
2. **内容结构** — 识别叙事节拍（打斗/动作/转折/情绪/对白/氛围），不同节拍给予不同视觉停留时间

动作镜头留 1.5s 让观众看清，情绪镜头留 3s 让人物表情落地，对白镜头留 2.5s 保证台词说完。

> 💪 **打斗场景自动增强**：文本命中打斗信号（交手/过招/格挡/挥剑/拔刀/开枪…，静态持械不算）时判为 `fight` 节拍——时间线自动加密到 2-4s/拍短拍快切，每拍按文本注入动作片镜头语言（挥击带动态模糊残影、格挡火花迸溅、受击反应、末拍瞬间慢动作特写），并追加打斗氛围段。详见 `references/prompt-guide.md`。

> ⚠️ 15 秒是**单镜上限**（豆包免费版硬限制），不是每镜的固定时长。镜头时长由上面两个因子算出，实际落在 8–14 秒区间；只有内容够满时才顶到 15 秒。

**分集与悬念结尾**（第三个因子，默认开启）：

```bash
python skills/doubao-manju-video/scripts/split_novel.py <章节文件> -o ./out --episode-shots 5   # 每集最多 5 镜
python skills/doubao-manju-video/scripts/split_novel.py <章节文件> -o ./out --is-final          # 完结章：末集正常收尾
python skills/doubao-manju-video/scripts/split_novel.py <章节文件> -o ./out --episode-shots 0   # 不分集
```

- **每集镜头数**：默认 5 镜。依据是行业惯例——主流微短剧单集 1–2 分钟，5 镜 ≈ 60 秒刚好落在下沿；同时 5 镜也约等于豆包一天的免费额度，即"一天一集"。
- **悬念结尾**：除完结章的最后一集外，每集必须停在"精彩部分过半之后"——即在高潮未解决处切断。判定方式是给镜头的叙事节拍打张力分（打斗/动作/转折 3.0、情绪 2.5、对白 2.0、叙述 1.0、氛围 0.5，含 `！？` 再 +0.5），张力 ≥ 2.0 的镜头才有资格收尾一集。
- 若某集尾部是低张力镜头，或原文含"终于/从此/恢复平静/再也没有"这类**归位词**（剧情已落地，没有钩子），脚本会把它顺延到下一集开头，让本集结尾落回高潮段。顺延后的集至少保留 2 镜，不推空。
- 若结尾内容实在切不出悬念（整集都是收束内容），脚本不硬造悬念，而是明确告警 `⚠️ 第 N 集结尾偏平`，提示合并到相邻集或人工补一个钩子镜头。

可选画风 `--style`：`3d-realistic`（默认，CG 写实 3D / 计算机生成仿真人）/ `3d-cartoon`（3D 卡通）/ `guoman-2d` / `anime` / `cinematic`（真人实拍观感）/ `ink-wash`。画风预设统一由 `shared/style_presets.py` 提供，与 doubao-character-ref 共享。

产出四个文件：

| 文件 | 用途 |
|------|------|
| `*.storyboard.md` | 人读分镜表，含镜号/时长/节拍/场景/运镜/对应原文 |
| `*.prompts.txt` | 逐镜纯提示词，供手动复制或自动化脚本消费 |
| `*.voiceover.md` | 配音口播稿 + SRT 字幕（可直接导入剪映） |
| `*.shots.json` | 机读结构，供 `doubao_gen.py` 驱动浏览器 |

### 阶段 2B：故事描述 → 生成故事与分镜

输入不是小说章节时，先产出故事方案 JSON，再交给拆解器：

```json
{
  "title": "故事标题",
  "logline": "一句话讲清核心冲突",
  "setting": "世界观与主要场景",
  "characters": [
    {"name": "角色名", "desc": "外形/性格/年龄，务必具体"}
  ],
  "beats": [
    {"text": "这一镜发生了什么", "seconds": 12, "scene": "场景（可选）"}
  ]
}
```

`beats` 数量按目标时长定：每镜 8–15 秒，讲一个完整动作或情绪变化。**每个 beat 只承载一件事**，塞两件事就会超时。

然后：

```bash
python skills/doubao-manju-video/scripts/split_novel.py --from-plan plan.json -o ./out --style 3d-realistic
```

生成故事方案时的要求：
- 角色描述要写死外形特征（发色/服装/体型），否则每镜人物形象会漂移
- beats 按"起→承→转→合"组织，转折点单独占一镜
- 首镜建立场景，末镜收束情绪
- **连载故事按每 5 个 beat 一集规划**：结尾那镜要停在高潮未解决处（如"门忽然开了，站在门外的竟是——"），解答留给下一集开场；只有完结篇才让末镜收束情绪

### 阶段 3：自动生成视频

先 dry-run 确认内容，再实跑：

```bash
python skills/doubao-manju-video/scripts/doubao_gen.py out/xxx.shots.json -o ./videos --dry-run   # 预演
python skills/doubao-manju-video/scripts/doubao_gen.py out/xxx.shots.json -o ./videos             # 实跑
```

脚本会：打开豆包 → 逐镜填入提示词 → 提交 → **读取豆包回复的「视频生成参数确认」卡并自动二次确认**（豆包渲染前必先回参数卡求确认，脚本会解析模型/时长/比例/**风格**并与目标核对——若豆包沿用了卡通风格会告警）→ 轮询渲染 → 下载 mp4 → 关闭标签页。若豆包回复错误文案（额度/审核/失败），立即中止本镜而非空等超时。

常用参数：

| 参数 | 用途 |
|------|------|
| `--only 1,3,5` | 只生成指定镜头（失败重试用） |
| `--start 3 --end 8` | 生成区间 |
| `--continue-on-error` | 单镜失败不中断，继续下一镜 |
| `--keep-tab` | 保留浏览器标签，便于人工介入 |

**逐镜串行是刻意的**：并发提交会触发豆包限流，且免费额度本就有限。

### 阶段 4：交付

向用户汇报时给出：
- 镜头数、总时长、预计额度消耗
- 视频文件所在目录
- 字幕文件（用于配音剪辑）
- 失败镜头及重试命令

## 关键决策点

**遇到登录墙**：脚本不会退出——提示用户在专用浏览器窗口登录（截图留存），轮询等待最多 `--login-wait`（默认 600s）。登录后自动继续，无需重跑。若超时退出，用户登录完成后重跑即可，浏览器和登录态都已持久化。

**额度耗尽**：脚本把额度文案视为全局致命错误——当镜立即失败、**自动中断整批**（即使加了 `--continue-on-error`），汇总给出待补镜号和可直接复制的 `--only` 续跑命令。次日额度刷新后复制该命令续跑即可（已完成的镜头不在待补列表里，不会重复耗额度）。

**渲染超时**：超过 7 分钟未出片视为失败。可截图确认是否卡在"需要人工确认"的弹窗上。

**豆包改版导致选择器失效**：脚本采用多策略语义探测（不硬编码 class 名），且失败时会保存 DOM 快照。此时读取 `references/doubao-selector-guide.md` 中的排查流程重新校准。

**提示词效果不佳**：优先调整画风预设或运镜描述，而非加长提示词。豆包对自然语言理解良好，堆砌关键词反而会稀释重点。

## 用户可能要求的变体

| 需求 | 处理方式 |
|------|---------|
| 横屏 B站 | `--ratio 16:9` |
| 换画风（如要卡通而非仿真人） | `--style 3d-cartoon` 重新拆解后重跑；**画风走提示词层**，换风格必须重新拆解，不能中途改 |
| 水墨国风 | `--style ink-wash` |
| 只想要分镜不要视频 | 只跑阶段 2，用 `.storyboard.md` |
| 每集长度改一下 | `--episode-shots N` 重新拆解（默认 5 镜 ≈ 60s；`0` = 不分集） |
| 本章是完结章 | 加 `--is-final`，末集不再强制留悬念，正常收尾 |
| 结尾切不断，告警"结尾偏平" | 把该集与相邻集合并（`--episode-shots` 调大），或人工补一个钩子镜头 |
| 十几章批量做 | 逐章拆解，人工确认分镜后再统一生成，避免一次性消耗额度 |
| 已有分镜想改某镜 | 直接编辑 `.shots.json` 里该镜的 `prompt` 和 `seconds`，再 `--only N` 重生成 |

## 注意事项

- 一章内容通常产出 8–15 个镜头，总时长 2–3 分钟；按默认 5 镜/集即 2–3 集，正好对应 2–3 天的免费额度
- **分集是"播出单位"，分镜是"生成单位"**：豆包一次只能生成一个镜头，剪辑时按集拼接成片（每集的 SRT 已在 `*.voiceover.md` 里按集分段、时间轴从该集首镜重新计时）
- 免费额度有限（电脑端约每日 5 次生成，按次计费、与时长无关），生成前务必先 dry-run 确认无误
- **角色一致性**：跨章连载时建议先用 `doubao-character-ref` skill 生成角色六视图参考图，再用 `extract_characters.py` 从小说正文提取角色描述模板，每章生成时套用同一份描述
- 悬念结尾只切在**集**的边界，不切在章的结尾——章的结尾天然是下一章的起点，正好承接
- 原始素材（章节 txt、梗概 JSON）应保留，后续重生成时无需重新拆解
- CDP 客户端、页面操作原语、画风预设已提取到项目根的 `shared/` 模块，所有 skill 脚本共享同一套基础设施，新增其他风格的漫剧 skill 只需引用 `shared/` 即可

## 进阶：分镜衔接 + 构图量化 + 质量门（参考 shuohao-skills）

为解决跨镜画面不连贯、人物形象漂移、构图平庸的问题，本技能在 v2 升级中新增三项机制，详见 `references/prompt-guide.md`：

### 1. 分镜衔接字段（解决"上一镜结尾 → 下一镜开头无法衔接"）

`Shot` 新增三个衔接字段：

| 字段 | 作用 |
|------|------|
| `entry_state` | 进入本镜时画面已有的状态（承接上一镜收尾） |
| `exit_state` | 本镜结束时画面定格状态（供下一镜 entry_state 引用） |
| `blocking` | 站位/朝向描述 |

机制：第 N 镜 `exit_state` 由 `_infer_state_from_tail()` 从末句推断（动作/情绪/氛围三类匹配）；第 N+1 镜 `entry_state` 复用第 N 镜 `exit_state`。质量门 `validate_continuity()` 校验关键词重合。

### 2. 构图量化六字段（解决"视频效果不好"）

`Shot` 新增 `focal_length`/`camera_position`/`composition`/`gaze_target`/`focus_point`/`stability` 六字段，由 `COMPOSITION_BY_BEAT` 按节拍自动映射默认值。手改 `shots.json` 可覆盖。

### 3. 结构化角色圣经（解决"人物提示词薄弱"）

`characters.json` schema 升级为含 `persona`（age/gender/body/face/hair/clothing/props/distinguishing）+ `generic_identity`（video_term/frame_term）+ `aliases` + `importance`。`_generic_identity` 优先从 cast_map 取结构化字段，无则退化为原文正则推断。

### 4. 5 道质量门

`validate_shots()` 在拆解完成后跑 5 道核心校验，告警挂到 `ShotList.warnings`：

| 门 | 校验 |
|----|------|
| 1 | 单镜时长 ≤ 15s |
| 2 | 台词装得下（字数/秒数） |
| 3 | 同框 ≤ 3 人 |
| 4 | 衔接连贯（上一镜 exit_state → 本镜 entry_state 关键词重合） |
| 5 | 构图六字段齐全 |

### 5. CLI 新参数

```bash
python skills/doubao-manju-video/scripts/split_novel.py chapter.txt -o ./out \
    --characters-json path/to/characters.json \  # 注入结构化角色圣经
    --no-continuity                               # 调试模式：跳过衔接注入
```

### 6. 产物字段对比

| 字段类别 | 原有 | v2 新增 |
|---------|------|---------|
| 衔接 | — | blocking / entry_state / exit_state |
| 构图 | — | focal_length / camera_position / composition / gaze_target / focus_point / stability |
| 角色 | characters | on_screen_count |
| 角色 Bible | name + desc | aliases / importance / persona / generic_identity |
