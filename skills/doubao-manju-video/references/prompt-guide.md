# 漫剧提示词工程指南

豆包（Seedance 系列）对**自然语言描述**的理解优于关键词堆砌。本指南说明如何写出高命中率的镜头提示词。

## 提示词七要素结构

`build_prompt()` 生成的提示词遵循固定结构，缺一不可：

```
[画风] + [画幅与时长] + [场景] + [画面内容] + [运镜] + [光影] + [画质]
```

| 要素 | 作用 | 反例（应避免） |
|------|------|--------------|
| 画风 | 锁定视觉基调，跨镜一致 | 缺失 → 每镜风格漂移 |
| 画幅时长 | **时长必须写明**，否则模型自定 | "时长"缺失 → 可能只出 5 秒 |
| 场景 | 建立空间锚点 | 缺失 → 画面空洞 |
| 画面内容 | 一个镜头只说一件事 | "他打了敌人然后救了姑娘" → 两件事塞一镜必超时 |
| 运镜 | 决定镜头如何运动 | 缺失 → 默认静止，观感呆板 |
| 光影 | 决定氛围质感 | 缺失 → 平淡 |
| 画质 | 抑制画面崩坏 | "人物形象稳定不变形" 对长镜尤其重要 |

## 单镜只讲一件事

15 秒能承载的动作容量很有限。判断标准：

- ✅ 「金鱼跃出水面，在空中化作光影」——一个连续动作
- ❌ 「金鱼跃出水面，女主冲过来抱住它，然后两人一起飞走」——三件事，15 秒必然失控

若情节确实包含多个动作，拆成多个镜头，让节拍落在动作转折点上。

## 运镜与节拍匹配

不同叙事节拍需要不同运镜，否则节奏拖沓。`CAMERA_BY_BEAT` 已内置映射：

| 节拍 | 运镜 | 理由 |
|------|------|------|
| 打斗 | 打击点推近特写 / 环绕跟拍 / 低角度仰拍 / 手持晃动 按拍轮换 | 打击感与速度感，拒绝全程单一口吻 |
| 动作 | 跟随推进 + 手持晃动 | 增强临场感与冲击 |
| 转折 | 缓慢推近至面部特写 | 聚焦情绪变化 |
| 情绪 | 面部特写缓慢环绕 | 给观众读表情的时间 |
| 对白 | 过肩正反打 | 符合对话场景惯例 |
| 氛围 | 大远景横移摇镜 | 展示环境全貌 |

### 打斗场景自动增强（fight 节拍）

文本命中打斗信号时，`detect_beat` 判为 `fight`（优先于 `action`），自动获得动作片语言：

- **判定三路**：显性打斗词（打斗/交手/过招/格挡/围攻…）；枪战爆炸词（开枪/扫射/爆炸…）；兵器拳脚词 + 攻击动作词同现（挥剑/拔刀/拳打…）。静态持械（"握紧长剑"）、单纯移动（"拔腿就跑"）不会误判。
- **密集时间线**：普通镜 3-6s/拍，打斗镜 2-4s/拍（逐子句成拍，短拍快切）。
- **每拍注入镜头语言**（`FIGHT_BEAT_RULES`，按拍文本匹配）：挥击→"动态模糊残影，速度感强"、闪避→"衣袂翻飞"、格挡/寒光→"火花迸溅，打击点大特写"（火花仅双方兵器碰撞时出现，单方斩击为"剑锋寒光划过"）、倒地→"受击倒地，惯性前扑，打击感强"；末拍追加"瞬间慢动作特写"。
- **因果链编排**（`_fight_chain_desc`）：攻击拍后 1~2 拍内有倒地拍时，为该攻击拍标注攻击目标与命中部位（如"剑锋直取对方，命中其肩头"）；倒地拍写明被击中原因与失衡机制（如"被剑锋命中，重心失衡，向侧后踉跄倒地"）。兵器着力点按文本自动识别（剑锋/枪尖/拳头…），确保"出招→命中→倒地"因果连贯，避免人突然倒地。
- **氛围段**：自动追加"打斗氛围：动作凌厉，打击感与速度感强，金属碰撞与破空音效清晰。"

非打斗镜的提示词不受任何影响。

## 时长控制

镜头时长由两部分决定：

```
时长 ≈ 中文字数 / 4.6（朗读耗时）+ 2.0（视觉呼吸）+ 节拍补偿
节拍补偿：打斗 +2.0 / 动作 +1.5 / 转折 +2.0 / 对白 +2.5 / 情绪 +3.0 / 氛围 +3.5
```

情绪镜头天然需要更长时间——观众要看到表情变化，强压到 8 秒会显得仓促。

## 角色一致性（跨镜/跨章关键）

AI 视频最大的痛点是同一角色在不同镜头里长相不一致。缓解手段：

1. **固定外形描述**：每镜提示词重复同一套特征
   ```
   角色：苏见川，黑色短发，剑眉，星眸，穿青色长袍，腰悬玉佩
   ```
2. **固定画风前缀**：所有镜头用同一 `--style` 预设
3. **避免代词**：写「苏见川」而非「他」——代词会让模型丢失主体绑定
4. **关键角色可先出图再图生视频**：豆包支持图生视频，一致性更高（需手动上传参考图）

跨章连载时，把角色描述存成模板文件，每章生成时套用同一份描述。

## 画风预设速查

| key | 风格 | 适用题材 |
|-----|------|---------|
| `3d-realistic` | **CG 写实 3D（默认）**：计算机生成（CGI）/ UE5 级渲染，3D 建模仿真数字人，PBR 材质、皮肤次表面散射、真实毛发布料、物理光追；**非真人实拍、非卡通** | 都市、悬疑、言情、写实向短剧 |
| `3d-cartoon` | 皮克斯式 3D 卡通 | 全年龄、玄幻、儿童向 |
| `guoman-2d` | 国漫二维赛璐璐 | 仙侠、历史、热血 |
| `anime` | 日式新赛璐璐 | 校园、都市、青春 |
| `cinematic` | 写实电影质感（真人实拍观感，非 3D 渲染） | 悬疑、现实、都市硬核 |
| `ink-wash` | 水墨动画写意 | 古风、文言、诗意 |

画风前缀是每镜提示词的固定开头，**同一作品内不要中途换画风**。

### CG 写实 3D（`3d-realistic`）专项要点

CG 写实（计算机生成的仿真人，**不是真人实拍**）对"人味"的要求最高，三处必须写到位，否则容易退回卡通脸：

1. **风格前缀必须带双向反向约束**：预设里已内置「非真人实拍，非卡通，非动漫，非Q版，不要夸张五官与卡通化渲染」——前半句防止被识别为 `cinematic`（真人实拍），后半句防止回落卡通
2. **角色外形要写真实特征**：写「三十岁男性，颧骨分明，下颌线硬朗，留短寸头，穿深灰羊毛大衣」，不要写「大眼」「圆润」这类卡通词汇
3. **用写实渲染词汇**：「PBR 材质」「次表面散射」「光线追踪」「物理光照」优于「明快饱和」「卡通渲染」

> ⚠ CG 写实会**提高审核敏感度**（真人脸部特征更易触发）。规避：使用明显虚构的外形组合，避免具体明星姓名/肖像，避免血腥特写（见「审核友好化」）。

## 审核友好化

豆包对内容有审核机制。容易被拒的要素：

- 具体血腥描写（断肢、伤口特写）
- 恐怖面孔、尸体
- 真人明星姓名与肖像
- 敏感政治/宗教符号

规避方式：用「剪影」「暗部」「红色雾气」等替代直接描写；用虚构人名与场景；人物保持卡通化可大幅降低审核风险。

## 提示词调优路径

效果不好时按此顺序排查：

1. **画面太杂** → 精简「画面内容」到单一动作
2. **风格不对** → 换 `--style` 预设重生成，而非手动改词
3. **人物变形** → 强化「画质」段的「人物形象稳定不变形」，缩短该镜时长
4. **运镜呆板** → 在提示词中显式指定运镜方式
5. **时长不符** → 确认「时长N秒」已写入，N 取值范围 4–15
6. **跨镜人物不一致** → 用 `--characters-json` 注入结构化角色圣经，让所有镜头的通用身份由 `generic_identity.video_term` 统一取值
7. **跨镜画面跳变** → 检查 `shots.json` 中每镜 `entry_state`/`exit_state` 是否一致；不一致挂 `衔接不连贯` 告警
8. **构图平庸** → 改 `shots.json` 中该镜的六构图字段（焦距/机位/构图/视线/焦点/稳定性）

每次只改一个变量，才能定位真正起作用的因素。

## 分镜衔接（参考 shuohao-skills blocking 机制）

跨镜画面连贯是 AI 视频的难点。本技能在 `Shot` 数据结构中新增三个衔接字段：

| 字段 | 作用 | 示例 |
|------|------|------|
| `entry_state` | 进入本镜时画面已有的状态（承接上一镜收尾） | "剑已出鞘，寒光定格" |
| `exit_state` | 本镜结束时画面定格状态（供下一镜 entry_state 引用） | "背影远去" |
| `blocking` | 站位/朝向描述（人物站位、间距、与镜头关系） | "两人相对而立，间距约一臂" |

**衔接机制**：
- 第 N 镜的 `exit_state` 由 `_infer_state_from_tail()` 从该镜末句推断（动作/情绪/氛围三类模式匹配）
- 第 N+1 镜的 `entry_state` 直接复用第 N 镜的 `exit_state`
- 这套机制保证"上一镜的结尾 → 下一镜的开头"在画面状态上无缝承接

**质量门校验**：
- `validate_continuity()`：上一镜 `exit_state` 与本镜 `entry_state` 应有重合语义关键词，否则挂"衔接不连贯"告警
- 例如：上一镜"剑已出鞘，寒光定格" → 本镜"笑容定格，神情舒展" 会告警（无重合关键词）

**关闭衔接**：调试或独立单镜场景加 `--no-continuity` 参数跳过注入。

## 构图量化字段（参考 shuohao-skills 六字段）

`Shot` 新增六个构图量化字段，按节拍自动映射默认值（`COMPOSITION_BY_BEAT`）：

| 字段 | 含义 | 取值示例 |
|------|------|---------|
| `focal_length` | 焦距 | 广角16-24mm / 35mm标准 / 85mm中长焦 |
| `camera_position` | 机位 | 平视 / 低位仰视 / 高位俯视 / 过肩平视 |
| `composition` | 构图 | 三分法 / 居中 / 对角线动感 / 正反打 |
| `gaze_target` | 视线落点 | 对视 / 侧望 / 望向远方 / 低头 |
| `focus_point` | 焦点 | 人物面部 / 道具 / 远景环境 / 动作主体 |
| `stability` | 稳定性 | 稳定三脚架 / 手持轻微晃动 / 缓慢环绕 / 横移摇镜 |

**节拍默认映射**：

| 节拍 | 焦距 | 机位 | 构图 | 视线 | 焦点 | 稳定性 |
|------|------|------|------|------|------|--------|
| 打斗 | 广角16-24mm | 低位仰视 | 对角线动感 | 对视或侧望 | 动作主体 | 手持晃动跟随运动 |
| 动作 | 广角16-24mm | 低位仰视 | 对角线动感 | 对视或侧望 | 动作主体 | 手持轻微晃动 |
| 转折 | 85mm中长焦 | 平视特写 | 居中 | 对视 | 人物面部 | 稳定三脚架 |
| 情绪 | 85mm中长焦 | 平视面部特写 | 三分法 | 低头或侧望 | 人物面部 | 缓慢环绕 |
| 对白 | 50mm标准 | 过肩平视 | 正反打 | 对视 | 说话人 | 稳定固定机位 |
| 氛围 | 广角24-35mm | 高位俯视 | 三分法 | 望向远方 | 远景环境 | 大远景横移摇镜 |
| 叙述 | 35mm标准 | 平视中景 | 三分法 | 侧望 | 人物主体 | 缓慢平移 |

**覆盖默认值**：直接编辑 `shots.json` 中该镜的字段值， regenerate 时不会覆盖（除非重跑 `split_novel.py`）。

## 同框人数约束（参考 shuohao-skills ≤3 人硬门）

参考项目硬门：同框超过 3 人必须带拆解说明。本技能为软约束：

- `Shot.on_screen_count`：标注完角色后由 `_finalize_prompts` 回填 `len(shot.characters)`
- 超过 3 人挂 warning："镜 N 同框 M 人，建议拆镜或加群演虚化"
- 不强制拆镜：豆包有时能处理 4-5 人同框但效果会下降，由人工决策

**质量门校验**：`validate_shots()` 门3 检测，挂到 `ShotList.warnings`。

## 质量门（5 道核心，参考 shuohao-skills 18 道门）

本技能不照搬参考项目 18 道质量门（豆包单镜 8-14s 下很多门不适用），保留 5 道核心门：

| # | 门 | 校验内容 | 触发告警示例 |
|---|----|---------|------------|
| 1 | 单镜时长 | seconds ≤ 15s（豆包硬约束） | "镜 3 时长 18s 超过豆包 15s 上限" |
| 2 | 台词装得下 | 字数/秒数估算朗读耗时 ≤ seconds | "镜 2 旁白字数 80 字，朗读需 17.4s 超过镜头 10s" |
| 3 | 同框≤3人 | on_screen_count ≤ 3 | "镜 4 同框 5 人，建议拆镜或加群演虚化" |
| 4 | 衔接连贯 | 上一镜 exit_state → 本镜 entry_state 关键词重合 | "镜 2 衔接不连贯：上一镜收尾 '剑已出鞘…'，本镜承接 '笑容定格…'" |
| 5 | 构图字段齐全 | 六字段非空 | "镜 1 缺构图字段：focal_length,camera_position" |

告警挂到 `ShotList.warnings`，输出在 `*.shots.json` 的 `warnings` 字段，并在 stdout 打印 `⚠️` 行。

## v3：三类参考图 + 首尾帧衔接（跨镜衔接方案）

### 三类参考图（职责分离，不可混淆）

| 类别 | 编号 | 生成阶段 | 用途 |
|------|------|---------|------|
| 角色图 | C01-C13 | char_ref_gen.py | 保证人物脸型/服装/体型跨镜一致 |
| 道具图 | P01-P05 | char_ref_gen.py | 保证道具外观跨镜一致 |
| 场景图（尾帧图） | shot_NN_end | doubao_gen.py 阶段1 | 本镜结束定格画面，图生图生成 |

**角色图/道具图/场景图是三种不同的参考图，不要混淆。**
角色图是人物设定图（六视图），道具图是道具特写图，场景图（尾帧图）是镜头结尾的定格画面。

### 尾帧图生成（图生图）

每镜生成一张尾帧图，用角色图 + 道具图作参考（图生图模式）：
- **第一镜**：额外生成首帧图（`frame_prompt`），描述镜头开头定格
- **后续镜头**：只生成尾帧图（`end_frame_prompt`），首帧由视频生成阶段上传上一镜尾帧图作参考

`end_frame_prompt` 由 `split_novel.py` 的 `build_end_frame_prompt()` 生成，核心是 `exit_state`（本镜结束时的定格状态）。

### 首尾帧衔接（跨镜衔接核心机制）

从第 2 镜起，把上一镜尾帧图作为本镜首帧参考图上传，并在参考图说明里明确标注：
「本镜首帧画面，视频第一帧必须与该图一致（承接上一镜结尾）」。

```
E1 首帧图(新生成) → E1 尾帧图(新生成)
                                     ↓ 作为 E2 首帧参考上传
                                  E2 尾帧图(新生成)
                                     ↓ 作为 E3 首帧参考上传
                                  E3 尾帧图(新生成)
                                     ...
```

模型以上一镜尾帧画面为视觉锚点生成新内容，保证跨镜画面构图、人物站位、场景衔接流畅。

### 每镜上传的参考图

| 镜头 | 角色图 | 道具图 | 本镜首帧图 | 本镜尾帧图 | 上一镜尾帧图 |
|------|--------|--------|------------|------------|--------------|
| 第1镜 | ✅ | ✅ | ✅ | ✅ | ❌ |
| 第2+镜 | ✅ | ✅ | ❌ | ✅ | ✅（作为本镜首帧参考） |

### 命令行参数

```bash
# 阶段1：只生成关键帧图（尾帧+首镜首帧），不生成视频
python doubao_gen.py shots.json --char-refs char_refs_index.json --props-refs props_index.json --keyframes-only

# 完整流程：先生成关键帧图，再生成视频（含首尾帧衔接）
python doubao_gen.py shots.json --char-refs char_refs_index.json --props-refs props_index.json

# 跳过关键帧生成（复用已有 keyframes_state.json）
python doubao_gen.py shots.json --char-refs ... --skip-keyframes
```

### 断点续跑

关键帧图生成状态保存在 `<outdir>/keyframes_state.json`，中断后重跑会自动跳过已生成的关键帧。
