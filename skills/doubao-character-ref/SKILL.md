# 豆包角色参考图生成

为主要人物生成六视图角色设定图与道具特写图，保证漫剧跨镜/跨章的人物形象一致。

## 为什么需要这个技能

AI 视频生成最大的痛点是**同一角色在不同镜头里长相不一致**。豆包单镜独立生成，人物外形会在镜头间漂移。

解法：**先出角色参考图**——用豆包的图片生成能力，为每个主要角色生成一张"六视图设定图"（正面/背面/左侧面/右侧面/3/4 前视/3/4 后视），再为关键道具生成特写图。后续漫剧分镜提示词里引用这些参考图作为角色锚定，大幅降低漂移。

## 平台约束

- 豆包图片生成与视频生成**共享额度**（图片也消耗免费次数）
- 单张六视图图耗 1 次额度，单张道具图耗 1 次
- 免费版每日约 5 次——一次角色设定任务建议 ≤ 4 个角色 + 1 张道具，或 3 角色 + 2 道具
- 生成是**串行**的：一次一张，等出图再发下一条
- 六视图必须一张图出完（六个角度并排），不能分六次生成（否则六张图人物仍会漂移）

## 执行流程

### 阶段 0：浏览器就绪（与 doubao-manju-video 共用基础设施）

脚本零依赖、自包含：直连 CDP（内置 WebSocket 客户端），自动拉起带调试端口的专用配置浏览器。

**必须先向用户展示此提示，再启动浏览器操作：**

```
温馨提示：部分站点对浏览器自动化操作检测严格，存在账号封禁风险。已内置防护措施但无法完全避免，Agent 继续操作即视为接受。
```

建议先跑一次连通性体检（不消耗额度）：

```bash
python skills/doubao-character-ref/scripts/char_ref_gen.py --probe -o ./out
```

脚本行为与 doubao-manju-video 的 doubao_gen.py 一致：
- 检测 `--port`（默认 9222）是否已有可调试浏览器，有则直接复用
- 没有则自动拉起专用配置的 Edge（`%LOCALAPPDATA%\doubao-manju\edge-profile`），与用户日常浏览器并存
- 打开豆包并报告页面/登录状态
- 首次运行必须在专用窗口登录一次（持久有效）

### 阶段 0.5：从小说正文自动提取角色（可选）

如果手头已有小说章节文件，可先用 `extract_characters.py` 自动提取角色草稿，免去手写 JSON：

```bash
# 自动提取，输出到目录
python skills/doubao-character-ref/scripts/extract_characters.py chapter.txt -o ./out

# 预览结果不写文件
python skills/doubao-character-ref/scripts/extract_characters.py chapter.txt -o ./out --dry-run

# 交互式审校（逐角色确认/编辑/跳过）
python skills/doubao-character-ref/scripts/extract_characters.py chapter.txt -o ./out --interactive

# 指定画风（须与漫剧画风一致）
python skills/doubao-character-ref/scripts/extract_characters.py chapter.txt -o ./out --style 3d-realistic
```

提取策略（纯正则 + 频率分析，零第三方依赖）：

| 策略 | 信号来源 | 权重 |
|------|---------|------|
| 对话归属 | "苏见川道：""老者缓缓道" | ×3 |
| 引导词 + 人名 | "青年苏见川""白发老者" | ×2 |
| 主语 + 动作动词 | "苏见川握着""老者摇头" | ×1 |
| 副词 + 道说 | "苏见川缓缓道" | ×2 |

出现频率 ≥ 2 的候选保留为主要角色。当具名角色不足 2 个时，自动兜底提取通用称谓（老者/青年/女子等）。

产出 `*.characters.json`，格式与阶段 1 的手写 JSON 完全一致，可直接作为 `char_ref_gen.py` 的输入。

> ⚠️ 自动提取是**草稿**——外形描述可能不完整或不够精准。建议用 `--interactive` 逐角色审校，补全面部特征/发型发色等细节后再生成参考图。AI 对提示词的理解受描述精度影响极大。

### 阶段 1：准备角色定义

用户提供角色信息，或由阶段 0.5 的 `extract_characters.py` 自动产出。格式为 JSON：

```json
{
  "project": "雨夜来客",
  "style": "3d-realistic",
  "characters": [
    {
      "name": "苏见川",
      "desc": "三十岁男性，颧骨分明，下颌线硬朗，剑眉星眸，留短寸黑发，穿深灰色立领长风衣，腰悬玉佩，体型修长挺拔"
    },
    {
      "name": "林晚",
      "desc": "二十五岁女性，鹅蛋脸，柳眉杏眼，长发及腰微卷，穿白色棉麻长裙，外搭米色针织开衫，气质温婉"
    }
  ],
  "props": [
    {
      "name": "玉佩",
      "desc": "半月形白玉佩，表面雕云纹，边缘温润有包浆，穿红丝穗，古风挂件"
    }
  ]
}
```

角色描述要求（直接决定一致性质量）：

| 要素 | 必须写明 | 反例 |
|------|---------|------|
| 年龄/性别 | "三十岁男性" | "他" |
| 面部特征 | 颧骨、眉形、眼形、下颌线 | "帅气" |
| 发型发色 | "短寸黑发" | "好看的头发" |
| 服装 | 款式、颜色、材质、配饰 | "穿着得体" |
| 体型 | 修长/壮硕/纤细 | 缺失 |

> 写死外形特征是跨镜一致性的根基。模糊词（"帅气""漂亮"）会让模型每次画不同的人。

### 阶段 2：生成角色参考图

```bash
# 用角色定义 JSON 生成（可来自手写或 extract_characters.py 自动提取）
python skills/doubao-character-ref/scripts/char_ref_gen.py characters.json -o ./char_refs

# dry-run 预览将发送的提示词
python skills/doubao-character-ref/scripts/char_ref_gen.py characters.json -o ./char_refs --dry-run

# 只生成指定角色
python skills/doubao-character-ref/scripts/char_ref_gen.py characters.json -o ./char_refs --only 1,2
```

脚本会：打开豆包 → 逐角色发送六视图提示词 → 等出图 → 下载 → 逐道具发送道具特写提示词 → 下载 → 关闭标签页。

每个角色产出一张 `{角色名}_六视图.png`，每个道具产出一张 `{道具名}_道具.png`，外加一份 `char_refs_index.json` 索引。

### 阶段 3：与漫剧分镜联动

生成的参考图索引 `char_refs_index.json` 可被 `split_novel.py` 消费：在分镜提示词里自动注入角色描述模板，保证跨镜复用同一套外形描述。

漫剧 SKILL.md 中「角色一致性」一节已说明：把角色描述存成模板文件，每章生成时套用同一份描述。本技能就是产出并管理这份模板的工具。

## 提示词结构

六视图提示词遵循固定模板（详见 `references/prompt-guide.md`）：

```
[画风] + 角色设定图，六视图并排：
[角色名]，[外形描述]
六个角度：正面全身、背面全身、左侧面、右侧面、3/4前视、3/4后视
六个角度同一人物，五官服装完全一致
[画质约束]
```

画风预设与 doubao-manju-video 完全一致，统一由共享内核 `shared/style_presets.py` 提供（`3d-realistic` / `3d-cartoon` / `guoman-2d` / `anime` / `cinematic` / `ink-wash`），保证参考图与最终视频画风统一。

## 关键决策点

**遇到登录墙**：与 doubao-manju-video 相同——脚本不退出，提示用户在专用窗口登录，轮询等待最多 `--login-wait`（默认 600s）。

**额度耗尽**：脚本把额度文案视为全局致命错误——当张立即失败、自动中断整批，汇总给出待补角色/道具和续跑命令。

**出图超时**：单张图片生成通常 30–90 秒。超过 5 分钟未出图视为失败，保存截图与 DOM 快照供排查。

**六视图出图不完整**：豆包偶尔只画出 4 个角度。此时该参考图仍可使用（标注缺失角度），或用 `--retry` 重新生成该角色。

**画风与漫剧不一致**：参考图的 `--style` 必须与漫剧分镜的 `--style` 一致，否则参考图锚定效果会打折扣。

## 用户可能要求的变体

| 需求 | 处理方式 |
|------|---------|
| 只出角色不出道具 | characters.json 里 `props` 留空数组 |
| 补某个角色 | `--only N` 只生成指定编号 |
| 换画风 | `--style 3d-cartoon` 重新生成（必须与漫剧画风同步） |
| 只要提示词不出图 | `--dry-run` 打印全部提示词 |
| 已有角色图想加道具 | 编辑 JSON 加 props，`--only-props` 只跑道具部分 |
| 角色太多额度不够 | 分批跑：今天 3 个角色，明天补剩余 + 道具 |

## 注意事项

- 角色参考图是**一次性投入**：角色定稿后生成一次，后续所有章节共用，不需要每章重出
- 六视图必须**一张图出六个角度**，不能分六次单角度生成——后者无法保证六张是同一个人
- 道具图优先选**与角色有强关联的关键道具**（角色的标志性物件），非必要道具不浪费额度
- 参考图下载后，建议人工检查五官/服装一致性再投入漫剧生产
- 两个 skill 共用同一个浏览器配置和登录态，无需分别登录
- CDP 客户端、页面操作原语、画风预设已提取到项目根的 `shared/` 模块，所有 skill 脚本共享同一套基础设施
